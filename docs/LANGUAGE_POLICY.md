# RF Sentinel — Мовна політика

## Мета й основна мова

Основна мова нової проєктної документації для людей і пояснювального тексту — українська. Документація має допомагати Product Owner розуміти проєкт, контролювати процес і брати участь у review архітектурних та проєктних рішень без мовного бар'єра.

## Технічна термінологія

Технічні identifiers, назви класів та інтерфейсів, API, CLI-команди, filenames, назви пакетів, протоколів і технологій, Git-термінологію та усталені engineering terms можна й варто залишати англійською, коли це забезпечує однозначність. Наприклад: `DeviceManager`, `RFEvent`, `AcquisitionAdapter`, `systemd`, `commit`, `branch`, `Pull Request`.

Не слід створювати штучні переклади identifiers. Source code, identifiers, API names і machine-facing configuration не перекладаються заради стилістичної чи мовної уніфікації.

## Поступовий переклад і review

Наявні англомовні architecture/research documents не перекладаються автоматично. Їх можна перекладати поступово, окремими змінами, придатними для review, за схваленням Product Owner.

Переклад не повинен непомітно змінювати технічний зміст, межі проєкту, силу вимог або статуси рішень. Зміни архітектури чи вимог потребують звичайного review незалежно від мови; ця мовна політика не є підставою для їх прийняття.
